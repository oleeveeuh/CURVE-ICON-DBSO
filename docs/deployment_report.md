# Deployment report — public synthetic track (measured, not targeted)

**Every number below is a measurement taken from the deployed synthetic
environment or its artifacts — never an acceptance target restated as a
result.** The environment carried **synthetic data only** at all times
([data_access.md](data_access.md)); no real data, real artifacts, or
real-derived material ever existed in it. All of it is research
equipment verification — **not for clinical use, and not a clinical or
scientific result of any kind.**

## 1. What ran

- **Stack** (`infra/`, single root per [ADR-005](decisions/ADR-005-terraform-organization.md)):
  VPC (no NAT) → internet-facing ALB (origin-facing security group locked
  to the CloudFront prefix list + secret `X-Origin-Verify` header) →
  ECS Fargate task (0.25 vCPU / 0.5 GB, non-root, desired 0 when idle) ←
  CloudFront (default `*.cloudfront.net` domain, HTTPS-only viewers,
  [ADR-004](decisions/ADR-004-public-ingress-and-tls.md)); private versioned
  S3 artifact bucket; 14-day log group; 4 OBS-002 alarms → SNS email
  topic; CloudWatch dashboard; $5/$20 budget notifications.
- **Image**: built once per commit SHA, pushed to ECR immutable-tag
  repository `curve-icon-dbso-dev-api`, deployed **by digest** (never by
  tag). Head of the verified line: `sha-69313a440d45` =
  `sha256:bbf920f5…569d`, task definition revision line converged on `:7`
  after the rollback exercise, deployment rollout `COMPLETED`, service
  steady state.
- **Endpoints verified through CloudFront**: `/ready`, `/health`,
  `/model-info`, `/predict` (schema-valid synthetic batches of 1–8 rows;
  schema hash echoed by the service matched the artifact manifest).

**Throughput honesty note (2026-11-16 review):** the ramp shape tops out
at ~1 request/s/user, so 50 users produced ~38 measured req/s — the
**50 req/s acceptance target was not reached** by this run. The
excellent p95 (110 ms) and zero failures are valid *at the measured
load only* and do not establish performance at 50 RPS. Remaining work:
a constant-throughput Locust profile that sustains ≥ 50 **measured**
RPS for the planned duration, rerun against a fresh deployment.

Per-endpoint p95: `POST /predict` (27,362 req) 110 ms; `GET /ready`
(6,765 req) 110 ms.

## 4. Drift demonstration (OBS-006/OBS-007) — 2026-11-15, re-run fresh on the current locked environment

Reference aggregates are baked into the synthetic artifact at training
time (versioned, aggregate-only: quantile bin edges + expected shares of
the synthetic training cohort — no per-row data). PSI is computed per
feature by `scripts/drift_demo.py` against two deterministic synthetic
samples (n = 500 each, cohort seed = training seed 42):

| Sample | Max PSI | Features above 0.2 | Exit |
|---|---|---|---|
| Clean (reference-distributed) | **0.0052** | **none** | 0 |
| Shifted (50 % shift fraction) | **12.6** (min 10.1) | **all 7** | 0 |

**Disclaimer (repeated in every report the tool emits):** PSI > 0.2 here
is a documented *educational* warning convention. This is **not**
validated clinical drift monitoring, the reference is a synthetic
cohort, and nothing here supports a clinical or model-decay claim. The
report contains aggregate PSI floats and bucket shares only — never raw
feature values, never per-row data, never sparse buckets.

## 5. Failure and rollback exercise (owner-run) — 2026-11-15

Mechanism: image built with `--build-arg FAILURE_DEMO=1` removes the
trained artifact, so the fail-closed readiness path (MOD-003) returns
503 forever and the deployment fails ALB health checks.

| Step | Measured |
|---|---|
| Failure image deployed → targets unhealthy | **~40 s** |
| `*-unhealthy-targets` alarm state → ALARM | fired during the breach window |
| Deployment circuit breaker rollback to prior known-good revision | **~70 s** (`:6` → `:5`) |
| Dropped user requests during rollback | **0** — the service answered 200 throughout |
| Convergence back to the good digest | applied; final state revision `:7`, rollout `COMPLETED`; a second plan reported **no changes** (INF-010) |

Alarm→SNS **delivery plumbing** was exercised by forcing alarm states
with `set-alarm-state` (the OK-state reason "delivery test complete"
was still visible at teardown). **Email delivery was never observed by
a human**: the subscription stayed `PendingConfirmation` (one-time
owner click) for the whole life of the environment, and the pending
subscription was removed with the topic at destroy — the next apply
sends a fresh confirmation email.

## 6. Observability verification (OBS-001/OBS-002)

- Application logs are **metadata-only JSON lines**: `duration_ms`,
  `error_class`, `model_version`, `request_id`, `route`, `row_count`,
  `schema_hash`, `status`. Enforced by tests
  (`test_logs_are_metadata_only_and_json`,
  `test_log_lines_never_contain_payload_or_prediction_values`) and
  re-checked live: no payload bytes or feature values in any log line.
- Two log metric filters, low-cardinality by construction:
  invalid-input counts dimensioned **only** by the fixed app-defined
  `error_class`; restart counts from the uvicorn startup line. No
  payload-derived dimension exists anywhere in the telemetry stack.
- Four alarms wired to the SNS topic with `ActionsEnabled = true`
  (5xx-ratio, target p95, unhealthy targets, unexpected restarts);
  dashboard `curve-icon-dbso-dev-dashboard` covered requests, status
  classes, p50/p95, target health, task CPU/memory, restarts, invalid
  inputs by class, and deployed model-version visibility via a Logs
  Insights widget.
- Observed idle behavior (honest note): with the service scaled to zero
  the p95 alarm reads `INSUFFICIENT_DATA` (`treat_missing_data =
  "missing"` — unknown, not healthy); the 5xx and restart alarms use
  `notBreaching` and stay `OK`.

decision (ADR-004, plan §14), the environment was **destroyed between
milestones** rather than left burning.

## 8. Teardown evidence (2026-11-15)

1. `terraform plan -destroy`: **50 to destroy, 0 to add, 0 to change**.
2. First destroy pass: 49 resources removed; **one failure** — the ECR
   repository is not `force_delete` and still held two images
   (`RepositoryNotEmptyException`). Both images were deleted via
   `batch-delete-image`, and a second pass removed the empty repository
   (`Resources: 1 destroyed`). This two-step is now documented in
   [runbook.md](runbook.md) §9.
3. **After-destroy orphan check (§10): all empty** — ECS clusters, ALB,
   target groups, NAT gateways, stray public IPs, ECR repositories,
   CloudFront distributions, SNS topics, log groups, dashboards, alarms,
   budgets, and artifact buckets all returned zero matches.
4. **Intentionally retained** (INF-006): the remote-state bucket
   (`curve-icon-dbso-tfstate-*`) and its DynamoDB lock table.
   `terraform state list` is empty.
5. Budgets are part of the main module: destroyed with it; recreated on
   the next apply.

## 9. Reproducibility of this report

The environment is disposable by design; every number above can be
reproduced by redeploying per [runbook.md](runbook.md) §3–§5 (one
`terraform apply` with the full variable set) and re-running §8c–§8e.
The full apply-warning (always pass `container_image` +
`desired_count`) exists because an observability apply that omitted the
variables once silently scaled the service to zero — it was caught by
the §5 verify step within minutes.
